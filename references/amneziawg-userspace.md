# AmneziaWG на userspace-демоне `amneziawg-go`

Рецепт для случая, когда kernel-модуль недоступен (контейнерная виртуализация OpenVZ/LXC,
Secure Boot, нет заголовков ядра) или намеренно не нужен, а обфускация нужна настоящая.
Отработан на двух VPS с Ubuntu 24.04 (1–2 vCPU).

## Почему не wg-easy

Автодетект wg-easy смотрит только на kernel-модуль. **Без модуля он молча откатывается
на обычный WireGuard** — туннель поднимется, обфускации не будет, и снаружи это выглядит
как рабочий VPN. `amneziawg-go` в образе wg-easy есть, и с `OVERRIDE_AUTO_AWG=awg`
`awg-quick` должен запустить его сам — но этот путь не документирован и здесь не проверялся.
Если модуль ставится (PPA или исходники, раздел 4 SKILL.md; на 24.04 и 26.04 собирается) —
проще wg-easy с модулем.

## Потолок клиента при раздаче native `.conf`

I1–I5 — это фича AmneziaWG **1.5**. Версию 2.0 отличают S3/S4 плюс H1–H4 как
**диапазоны** (`H1 = start-end`). Демон `amneziawg-go` их принимает, **но клиент AmneziaVPN
4.8.x (июль 2026) не honorit H-диапазоны из импортированного native `.conf`** — хендшейк
не проходит, сервер отвергает заголовок вне диапазона. На нём через раздачу `.conf`
достижима **1.5**: I1 (QUIC-сигнатура на хендшейке) работает, проверено tcpdump.

Клиенты AmneziaVPN 5.0.0.5+ заявляют поддержку 3.0, 5.0.1.5+ — 3.1; импорт native `.conf`
с H-диапазонами на них здесь **не перепроверялся**. Прежде чем раздавать `.conf` с 2.0/3.x —
проверить хендшейк на одном устройстве с актуальной версией клиента. Без такой проверки
держаться 1.5.

## Шаги

1. **`amneziawg-go`** — кросс-собрать на маке, не грузить сервер сборкой:
   `git clone amnezia-vpn/amneziawg-go`,
   `CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -ldflags="-s -w" -o awg-go .`,
   `scp` → `/usr/local/bin/amneziawg-go` (0755). ~3.4 МБ статик.
   **Версию фиксировать явно** (тег, не master): в 3.0 и 3.1 менялась семантика S1–S4
   и добавлялись ключи. Тег `amneziawg-go` и `amneziawg-tools` брать одного поколения.
2. **`amneziawg-tools`** — собрать на сервере (нужен `build-essential`):
   `git clone`, `cd src && make && sudo make install` → `awg`, `awg-quick`.
   **Не метапакет `amneziawg` из PPA:** он тянет DKMS-модуль, а загруженный модуль
   перехватил бы интерфейс у userspace-демона.
3. `awg-quick` сам падает в userspace (`${WG_QUICK_USERSPACE_IMPLEMENTATION:-amneziawg-go}`)
   при отсутствии kernel-модуля — переменная окружения не нужна.
4. Конфиг `/etc/amnezia/amneziawg/awg0.conf` (root:600): `Address`, `ListenPort`,
   `PrivateKey`, обфускация `Jc/Jmin/Jmax`, `S1`, `S2`, `H1`–`H4` (4 разных uint32 > 4),
   `I1 = <b 0xc700000001><rc 8><t><r 100>` — QUIC-мимикрия.
   - **Порт брать выше `ip_local_port_range`** (обычно 32768–60999): порт из этого
     диапазона может оказаться занят исходящим сокетом ровно в момент подъёма интерфейса
     после ребута.
   - В `PostUp` — MASQUERADE для своей подсети и **MSS clamping**: без него хендшейк
     и пинг проходят, а часть HTTPS-сайтов молча виснет (операторы режут ICMP frag-needed).
   - **FORWARD-правила из `PostUp` не переживают загрузку, если на хосте есть Docker:**
     он стартует следом и пересобирает цепочку. Их место — `/etc/ufw/before.rules`
     (`ufw-before-forward`). Цепочки UFW Docker не трогает.
   - В клиентских конфигах `AllowedIPs = 0.0.0.0/0, ::/0`. `::/0` обязателен, если
     у сервера нет глобального IPv6: без него весь v6-трафик клиента пойдёт мимо туннеля
     и раскроет реальный адрес.
5. `awg-quick up awg0`; `systemctl enable awg-quick@awg0`; UFW `allow <port>/udp`.
6. **Скрипт раздачи** `/usr/local/sbin/awg-add-client <имя> [срок]` (root:700): берёт
   следующий IP, тянет обфускацию и I1 из `awg0.conf`, добавляет пира вживую (`awg set`)
   и в конфиг, печатает QR и `.conf`, кладёт в `/root/awg-clients/`.
   **Роутеру срок не ставить** — cron просрочки снесёт туннель целой площадки молча.

## Грамматика CPS-тегов

Грамматика демона = документация Amnezia: `<b HEX>` фиксированные байты, `<t>` timestamp
4 байта, `<r N>` random N байт, `<rc N>` random alnum, `<rd N>` random digits.
Тег `<c>` убран в новых версиях.

## Что НЕ включать

**S3/S4** — паддинг каждого транспортного пакета. Шифрование и так в userspace; на 1–2 vCPU
это прямая потеря скорости. Всё «бесплатное» (I1, H1–H4, S1/S2, Jc — только хендшейк)
уже включено.

## Проверка обфускации

Только tcpdump на проводе, сигнатура `c7 00 00 00 01`. `awg show` на сервере её не покажет.

**I-пакеты шлёт инициатор хендшейка — и это бывает сервер.** Проверено tcpdump:
при скачивании rekey инициировал сервер (три пакета `сервер → клиент` длиной 117
с нужной сигнатурой, встречных от клиента за 90 с — ноль). Искать сигнатуру
только во входящем трафике = увидеть «обфускации нет» при рабочей обфускации.

Остальные проверки после `up`: процесс `amneziawg-go`, `ip addr show awg0`,
`ss -ulnp | grep <port>`, `awg show`, FORWARD-правила на месте, MASQUERADE только
для своей подсети (не задеть Outline/docker). End-to-end — с клиента: хендшейк на сервере,
внешний IP, tcpdump на сигнатуру.

# Диагностика: «клиент не подключается»

Симптом: AmneziaWG-клиент долго подключается / не подключается / «трафик не идёт».
Порядок сработал за ~15 минут, причина в том разборе оказалась **не на сервере**,
а на устройстве — подключён был не тот `.conf`.

1. **`sudo awg show awg0` на сервере.** Если у пиров нет `endpoint`/`latest handshake`/
   `transfer`, а `ip -s link` показывает RX=0 → пакеты не обрабатываются. Проверить
   заодно: `sysctl net.ipv4.ip_forward` (=1), MASQUERADE для своей подсети
   (`iptables -t nat -S POSTROUTING`), ACCEPT для интерфейса (`iptables -S FORWARD`),
   `ufw status`, `ss -ulnp | grep <port>`.
2. **Где теряются пакеты — tcpdump с двух сторон одновременно.** Если на сервере идут
   ТОЛЬКО входящие и ни одного ответа наружу → сервер получает, но не отвечает,
   то есть отвергает handshake.
3. **Прямая улика — verbose-лог демона.** Drop-in
   `/etc/systemd/system/awg-quick@awg0.service.d/verbose.conf`:
   `[Service]` + `Environment=LOG_LEVEL=verbose` → `daemon-reload` +
   `systemctl restart awg-quick@awg0` → `journalctl -u awg-quick@awg0 -f`. Читать так:
   - `Received message with unknown type` ×Jc — это junk-пакеты, **норма**;
   - **`Received invalid initiation message`** — handshake расшифрован, но крипто
     не сошлось (MAC/ключ). Это **не тот серверный ключ или устаревший конфиг
     на устройстве. НЕ обфускация и НЕ MTU**;
   - `Received handshake initiation` + появившийся endpoint в `awg show` — успех.

   **После — убрать drop-in** (`rm` + `daemon-reload`).
4. **Подтверждение «дело в устройстве»:** один клиент со свежим конфигом работает,
   другие со старыми — `invalid initiation`. Сверить: pubkey из клиентского `PrivateKey`
   через `awg pubkey` = серверный peer для его IP; параметры `Jc/S1/S2/H1-4/I1` клиента =
   `awg show`. Фикс — переимпортировать актуальный `.conf`/QR, серверных правок не требуется.

**Мораль:** начинать с `awg show` (есть ли handshake у пиров) и verbose-лога,
а не с перебора NAT и MTU.
